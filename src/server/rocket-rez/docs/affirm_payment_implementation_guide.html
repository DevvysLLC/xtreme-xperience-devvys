Rocket Headless Checkout – Payments With Redirect Integration Guide

This document describes how to integrate the Rocket Headless payment iframe with Stripe payments that use redirects (like Affirm):

  • Affirm (our use case in this document) redirects back to your site (the parent page) where the Rocket Headless payment project is embedded.
  • The embedded Headless Checkout project automatically resumes and completes the payment.
  • Sensitive Stripe query parameters are not left in the final URL.

1. Overall Flow

  1. Your page (the parent) hosts the Rocket Headless payment project in an <iframe>.
  2. You create a cart, obtain a Stripe clientSecret, and send a PROCESS_PAYMENT message to the iframe with:
    • A paymentRequest object that includes cart and customer details.
    • A returnUrl that points back to your parent page (this is a new property of the paymentRequest object).
  3. The user chooses Affirm; Stripe/Affirm redirects the top-level window to the returnUrl.
  4. Your parent page:
    • Reads Stripe/Affirm query params (e.g. payment_intent_client_secret, redirect_status).
    • Immediately strips those params from the URL (using history.replaceState).
    • Restores the checkout state from sessionStorage.
    • Reloads the iframe and sends an INIT message to it.
    • After a subsequent READY message returned from the iframe, sends a RESUME_PAYMENT message with the clientSecret and stored state.
  5. The iframe responds to RESUME_PAYMENT by capturing/processing payment then:
    • Sends PAYMENT_AUTH_SUCCESS / PAYMENT_AUTH_ERROR / PAYMENT_SUCCESS / PAYMENT_ERROR back to the parent via postMessage.
  6. Your parent updates its UI or redirects users to success/error pages based on these messages.
Note: You do not need to replicate any React code; your integration only needs to send and receive messages to/from the iframe as shown below.

2. Sending PROCESS_PAYMENT with returnUrl and Saving State

Before sending the user to Affirm, build a paymentRequest as you currently do that includes a new property called returnUrl pointing back to your current page (the page where the Headless client is embedded), and save all the data needed to resume later (I'm using sessionStorage but you can use what you'd like).

I've included a snippet below that stores this data using a persistParentRedirectState method that gets called before the PROCESS_PAYMENT message is sent. You can persist state however you like, but it MUST be saved before you send the PROCESS_PAYMENT message so that in case the user does use a payment method (like Affirm) that uses redirects, they get redirected to the right location. 

// A key used to store state between redirect out to Affirm and return back.
const REDIRECT_STATE_KEY = 'headless_parent_redirect_state';

// Save the state we need to resume later.
function persistParentRedirectState(paymentRequest) {
  try {
    const state = {
      cartId,        // your internal cart ID
      cartToken,     // headless cart token / JWT
      userGuid,      // your user identifier (optional)
      paymentMethodId: parseInt(document.getElementById('paymentMethodId').value),
      paymentRequest,
    };
    sessionStorage.setItem(REDIRECT_STATE_KEY, JSON.stringify(state));
    log('Persisted parent redirect state to sessionStorage');
  } catch (e) {
    log('Failed to persist redirect state: ' + (e && e.message ? e.message : e));
  }
}

function sendProcessPaymentToIframe() {
  if (!clientSecret) {
    log('Cannot send PROCESS_PAYMENT: clientSecret not available');
    return;
  }

  // Compute a base URL from the current page (you can use whatever valid URL you'd like, this was just my implementation).
  const currentBaseUrl = (window.location.origin + window.location.pathname).split('?')[0];

  const paymentRequest = {
    PaymentMethodId: parseInt(document.getElementById('paymentMethodId').value),
    CartId: cartId,
    PaymentTotal: parseFloat(document.getElementById('paymentTotal').value),
    RecaptchaToken: document.getElementById('recaptchaToken').value || null,

    // Where Stripe/Affirm should redirect the top-level browser back to:
    // parent page URL + #checkout-iframe (or any anchor you like if you'd like to use one. 
    //I found it a good UX to redirect user back to the Stripe iFrame).
    returnUrl: `${currentBaseUrl}#checkout-iframe`,

    FirstName: document.getElementById('firstName').value,
    LastName: document.getElementById('lastName').value,
    Email: document.getElementById('email').value,
    CompanyName: document.getElementById('companyName').value || null,
    MobilePhoneNumber: document.getElementById('mobilePhoneNumber').value || null,
    HomePhoneNumber: document.getElementById('homePhoneNumber').value || null,
    EditCount: null,

    BillingAddress: {
      Address1: document.getElementById('address1').value,
      Address2: document.getElementById('address2').value || null,
      City: document.getElementById('city').value,
      CountryShortName2: document.getElementById('countryShortName2').value,
      ProvinceId: parseInt(document.getElementById('provinceId').value) || null,
      PostalCode: document.getElementById('postalCode').value,
    },

    SecondaryPayments: [],

    // (Optional) legacy duplicate address fields
    Address1: document.getElementById('address1').value,
    Address2: document.getElementById('address2').value || null,
    City: document.getElementById('city').value,
    CountryShortName2: document.getElementById('countryShortName2').value,
    ProvinceId: parseInt(document.getElementById('provinceId').value) || null,
    PostalCode: document.getElementById('postalCode').value,

    SMSConsent: document.getElementById('smsConsent').checked,

    CreditCard: {
      Type: null,
      Cvv: null,
      Expiry: null,
      Name: `${document.getElementById('firstName').value} ${document.getElementById('lastName').value}`,
      Number: null,
      Track1: null,
      MagTekKSN: null,
      DigitalWalletType: null,
    },

    allowSecondaryPayments: document.getElementById('allowSecondaryPayments').checked,
  };

  // Persist state before redirect.
  persistParentRedirectState(paymentRequest);

  const messageToIframe = {
    type: 'PROCESS_PAYMENT',
    clientSecret: clientSecret,
    paymentRequest: paymentRequest,
    cartToken: cartToken,
    userGuid: userGuid,
  };

  const iframe = document.getElementById('checkout-iframe');
  iframe.contentWindow.postMessage(messageToIframe, '*');

  log('Sent PROCESS_PAYMENT message to iframe');
}

If you don't provide a returnUrl, it will default to the URL of the Headless Checkout project (https://secure.rocket-rez.com/rocketheadlessclient/ in production environment).

3. Handling the Return from Affirm on the Parent Page

After Affirm redirects back to your returnUrl, Stripe adds query parameters such as: payment_intent, payment_intent_client_secret, and redirect_status. You should:

  1. Read these parameters once.
  2. Strip them from the URL using history.replaceState so they are not visible in the address bar or history. Not required but good practice.
  3. Restore the saved checkout state from sessionStorage (or whatever you used to store the state in step 2).
  4. Reload the iframe and send an INIT message so it can get ready.
function getStripeRedirectParamsFromParentUrl() {
  try {
    const params = new URLSearchParams(window.location.search);
    const clientSecret = params.get('payment_intent_client_secret');
    const redirectStatus = params.get('redirect_status');
    if (!clientSecret) return null;
    return { clientSecret, redirectStatus };
  } catch {
    return null;
  }
}

function restoreParentStateAfterRedirect() {
  const redirectParams = getStripeRedirectParamsFromParentUrl();
  if (!redirectParams) return;

  // Immediately clean up sensitive Stripe/Affirm query params from the URL.
  try {
    const cleanUrl = window.location.origin + window.location.pathname + window.location.hash;
    window.history.replaceState({}, document.title, cleanUrl);
    log('Cleaned redirect query parameters from URL after Affirm/Stripe return.');
  } catch (e) {
    log('Failed to clean redirect URL: ' + (e && e.message ? e.message : e));
  }

  const rawState = sessionStorage.getItem(REDIRECT_STATE_KEY);
  if (!rawState) {
    log('No saved parent redirect state found, cannot resume payment.');
    return;
  }

  let state;
  try {
    state = JSON.parse(rawState);
  } catch (e) {
    log('Failed to parse saved redirect state: ' + (e && e.message ? e.message : e));
    return;
  }

  cartId = state.cartId;
  cartToken = state.cartToken;
  userGuid = state.userGuid;

  // Optional: repopulate visible form fields.
  if (state.paymentRequest) {
    document.getElementById('paymentTotal').value = state.paymentRequest.PaymentTotal ?? '';
    document.getElementById('firstName').value = state.paymentRequest.FirstName ?? '';
    document.getElementById('lastName').value = state.paymentRequest.LastName ?? '';
    document.getElementById('email').value = state.paymentRequest.Email ?? '';
  }

  const iframeUrl = document.getElementById('iframeUrl').value;
  const iframe = document.getElementById('checkout-iframe');
  iframe.src = iframeUrl;

  iframe.onload = function () {
    log('Iframe loaded after redirect, sending INIT...');
    const paymentMethodId = state.paymentMethodId;
    iframe.contentWindow.postMessage(
      {
        type: 'INIT',
        cartId: cartId,
        paymentMethodId: paymentMethodId,
        cartToken: cartToken,
      },
      '*',
    );
  };

  // Make redirect params available for the READY handler.
  window.__headlessRedirectClientSecret = redirectParams.clientSecret;
  window.__headlessRedirectStatus = redirectParams.redirectStatus;

  log('Restored parent state after redirect; waiting for iframe READY to resume payment.');
}

// Call on load because script is at the bottom of the page.
// If the script is placed in the Head tag then use DOMContentLoaded or window.onload to delay initialization until the DOM exists.
initializeUserGuid();
restoreParentStateAfterRedirect();

4. Handling READY and Sending RESUME_PAYMENT

After the iframe React app finishes its own initialization, it sends { type: 'READY' } to the parent. The parent uses this signal to either:

  • Start a new payment (initial flow) with PROCESS_PAYMENT, or
  • Resume an in-flight Affirm payment (return-from-redirect flow) with RESUME_PAYMENT.
window.addEventListener('message', function (event) {
  // Skip Stripe internal messages and telemetry.
  if (event.origin && event.origin.includes('.stripe.com')) return;
  if (containsStripeJsV3(event.data)) return;
  if (event.data.originatingScript) return;

  log(`Parent received message: ${JSON.stringify(event.data)}`);

  if (event.data.type === 'READY') {
    iframeReady = true;
    log('Iframe is ready for communication');

    if (window.__headlessRedirectClientSecret) {
      const iframe = document.getElementById('checkout-iframe');
      const stateRaw = sessionStorage.getItem(REDIRECT_STATE_KEY);
      let state = null;
      try {
        state = stateRaw ? JSON.parse(stateRaw) : null;
      } catch {}

      const resumeMessage = {
        type: 'RESUME_PAYMENT',
        clientSecret: window.__headlessRedirectClientSecret,
        redirectStatus: window.__headlessRedirectStatus || null,
        cartId: cartId,
        cartToken: cartToken,
        userGuid: userGuid,
        paymentMethodId:
          state && state.paymentMethodId
            ? state.paymentMethodId
            : parseInt(document.getElementById('paymentMethodId').value),
        paymentRequest: state && state.paymentRequest ? state.paymentRequest : null,
      };

      iframe.contentWindow.postMessage(resumeMessage, '*');
      log('Sent RESUME_PAYMENT message to iframe after redirect');
    } else if (clientSecret) {
      // Normal initial flow (no redirect in play).
      sendProcessPaymentToIframe();
    }

    tryEnablePayButton();
  } else if (event.data.type === 'PAYMENT_AUTH_SUCCESS') {
    const statusEl = document.getElementById('paymentStatus');
    statusEl.innerHTML =
      `✅ Payment Successful!<br>Payment Intent ID: ${event.data.paymentIntentId}<br>Status: ${event.data.status}`;
    statusEl.className = 'payment-status success';
    statusEl.classList.remove('hidden');
    log(`Payment successful: ${event.data.paymentIntentId}`);

    // Optional: redirect to your own success page here.
  } else if (event.data.type === 'PAYMENT_AUTH_ERROR') {
    const statusEl = document.getElementById('paymentStatus');
    statusEl.innerHTML = `❌ Payment Failed<br>Error: ${event.data.error}`;
    statusEl.className = 'payment-status error';
    statusEl.classList.remove('hidden');
    showError('paymentError', event.data.error);
    log(`Payment failed: ${event.data.error}`);
  }
});

5. Responsibilities for the Embedding Client

To integrate this flow, your application should:

  1. Render the Rocket Headless Checkout React app in an iFrame on your checkout page.
  2. When the user is ready to pay, the normal steps should be taken to build the paymentRequest object to send to the React Checkout app with the following additional steps for handling payments using redirects (e.g. Affirm):
    • The paymentRequest object now contains a returnUrl property:
      • This should be set to the URL where the React Checkout project is embedded and any anchor tags for specific page locations
      • Example: window.location.origin + window.location.pathname + '#checkout-iframe'.
      • If no returnUrl property is provided, the default (for production) is https://secure.rocket-rez.com/rocketheadlessclient/
    • Store { cartId, cartToken, userGuid, paymentMethodId, paymentRequest } in sessionStorage (or storage mechanism of your choosing) BEFORE sending a PROCESS_PAYMENT postMessage to the iframe. (I do this with the persistParentRedirectState function shown above.)
  3. After redirect from Affirm:
    • 1. Detect payment_intent_client_secret and redirect_status in the parent URL.
      • I do this using the getStripeRedirectParamsFromParentUrl method shown above
    • 2. Strip them from the URL with history.replaceState.
    • 3. Restore your saved state from sessionStorage.
    • 4. Reload the iframe and send INIT postMessage
    • NOTE: For steps 2-4, I've included an implementation in Section 3's code snippet. Please note that my implementation calls initializeUserGuid and restoreParentStateAfterRedirect (seen at the bottom of the code snippet) directly because my script is at the bottom of the file. If you have your script running in the HEAD tag, you may need to use DOMContentLoaded for the DOM to load before running javascript that may rely on it being fully loaded.
    • 5. After receiving READY message from React Checkout app, send RESUME_PAYMENT message.
    • 6. In the eventListener, update the READY message to determine whether we send a RESUME_PAYMENT message or a PROCESS_PAYMENT message
    • NOTE For steps 5-6, I've included an implementation in Section 4's code snippet.
  4. Listen for PAYMENT_AUTH_SUCCESS, PAYMENT_AUTH_ERROR, PAYMENT_ERROR, and PAYMENT_SUCCESS from the iframe to:
    • Show confirmation or error messages.
    • Optionally redirect the user to your own success/error pages.

With these steps in place, Affirm can safely redirect back to your site, the embedded Rocket headless checkout will automatically resume and complete the payment, and sensitive Stripe details will not remain in the URL.
