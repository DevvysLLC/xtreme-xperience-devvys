💫 Introduction

The Checkout API delivers offers functionality for client applications and integration partners to create and manage booking experiences. This high-level functional guide is intended to provide an overview on core concepts, resource structures, an end-to-end booking workflow, and key integration notes.

🚀 Getting Started

To begin using these APIs, you first must get your API credentials. Afterwards, make a POST request to the api/v1/oauth2/token endpoint with the following parameters in the request body:

  • client_id: this will be provided to you
  • client_secret: this will be provided to you
  • scope: for now use read_products
  • grant_type: this should always be client_credentials

You will be given a JSON Web Token (JWT) that expires in an hour. You will use that JWT to make future calls to the API by using it as the Bearer Token in the Authorization header.

For more information please see the token endpoint.

Guide

⭐ Key Concepts

  • Event Catalog: Events represent the experiences offered, each scheduled at specific dates and times. The Event Catalog provides data on available experiences, including timing details and constraints such as capacity limits. Applications can use this information to display options, enforce availability, and inform users of scheduling parameters.
  • Product Catalog: The Product Catalog includes all ancillary items that complement events, such as merchandise, gift cards, and memberships. It facilitates presentation of add-on offerings, and categorization of products for grouping and filtering purposes.
  • Cart: The Cart serves as a temporary holding area for selected events and products during the booking process. It maintains the state of chosen tickets, add-ons, and associated information while the user finalizes their selections. Operations on the Cart include item additions and removals, application of coupons, and facilitates payment.
  • Contact: Contact resources capture personal and billing information for purchasers and attendees. Each Contact contains details necessary for completing a booking, such as names, email addresses, etc.
  • Forms: Forms enable collection of additional data such as surveys, liability waivers, or custom questionnaires during the booking flow. Form templates are configured in RocketOffice and are retrieved through a set of endpoints to facilitate data capture. Submitted responses are linked to the cart.

🎟️ High-Level Booking Workflow

A typical booking transaction follows these steps:

  1. Discover Events & Products: Clients retrieve event and schedule listings to display available offerings prior to cart creation.

  2. Initialize Cart: A new cart session is created, using for subsequent operations.

  3. Add Items: Tickets or products are added to the cart, reserving inventory.

  4. Attach Contacts: Contact information for attendees is associated with the cart.

  5. Review Cart: The cart details are fetched, showing items, pricing, discounts, and taxes.

  6. Complete Checkout: Payment is authorized or captured using an iframe-based payment token.

  7. Receive Confirmation: An orderId is generated once payment is finalized.

💳 Payment Handling

Payments are collected via a secure, hosted iframe to ensure PCI compliance:

  • Session Creation: Request is made to the Checkout API to generate a one-time session URL. This URL points to a PCI-compliant payment form hosted on a secure domain. Embedding this URL within an iframe ensures that all sensitive input is isolated from client infrastructure.
  • Card Entry: End users interact directly with the hosted iframe to enter credit card or digital payment details. Since the form is served and managed by the payment gateway, raw card data is never exposed to or logged by client-side code or servers.
  • Tokenization: Once the user submits their payment information, the payment gateway validates the data and returns a single-use token.
  • Checkout Finalization: The token is submitted to the Checkout API to complete payment capture or authorization.
  • Error & Retry Handling: If the payment gateway returns an error (e.g., insufficient funds, network timeout), the API surfaces a structured error response. Client applications should listen for error events from the iframe, present user-friendly messages, and allow retrying without reloading the entire page.

🔔 Post-Booking UX & Notifications

After payment and booking confirmation, clients should plan their own UX and notification workflows. Key considerations include:

  • Custom Confirmation Page:

    • Decide on layout: booking reference, event summary, attendee details, and next-step guidance.

    • Provide clear links or buttons for printing tickets, adding to calendars, or browsing related offerings.

    • Consider upsell opportunities (e.g., add-on products or future events).

  • Emails & Tickets

    • Design branded email templates that summarize booking details, payment receipt, and support contacts.

    • Leverage the API to fetch ticket data.

    • Determine format (PDF attachment vs. embedded QR codes/serials) and timing (immediate vs. batched).

    • Plan pre-event reminders or updates; select trigger intervals (e.g., 24 hours before, one week before).
